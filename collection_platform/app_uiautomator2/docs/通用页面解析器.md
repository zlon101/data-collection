### 3. 多元素处理（严格遵循方案）

```python
✅ 找到0个：跳过
✅ 找到1个：保存
✅ 找到多个：
   ├─ 未配置 textPattern → 报错
   └─ 配置了 textPattern → 正则过滤

      ├─ 过滤后1个：保存
```

## 🎓 关键设计决策

### 1. 为什么使用 re.search？

```python
# re.search：包含匹配（更常用）
re.search(r"km|m", "1.2km")  # ✅ 匹配

# re.fullmatch：完全匹配
re.fullmatch(r"km|m", "1.2km")  # ❌ 不匹配
```

**理由**：用户期望的"包含匹配"语义

---

### 2. 为什么保留 max_scroll_times？

**场景**：底部标识配置错误
```
配置：bottom_indicator_resourceId = "错误的ID"
结果：永远检测不到 → 无限滚动 ❌

解决：max_scroll_times 作为兜底 → 滚动10次后报错 ✅
```

---

### 3. 为什么恢复 optional？

**需求**：区分必填和可选字段
```
场景：到达底部
├─ 必填字段未找到 → 报错 ❌
└─ 可选字段未找到 → 返回部分结果 ✅
```

## 📝 使用注意事项

### 1. 底部标识配置

```python
# ✅ 正确
bottom_indicator_resourceId="com.hpbr.bosszhipin:id/report_button"

# ❌ 错误

```

**验证方法**：
```bash
adb shell uiautomator dump /sdcard/window_dump.xml
adb pull /sdcard/window_dump.xml
# 打开 XML 文件，确认 resourceId 完整且唯一
```

---

### 2. textPattern 正则

```python
# ✅ 精确匹配距离
"textPattern": r"\d+\.?\d*\s*(km|m)"

# ❌ 过于宽松
"textPattern": r"m"  # 会匹配 "team", "employee"
```

---

### 3. optional 设置

```python
# ✅ 核心字段设为必填
"职位名称": {
    "resourceId": "...",
    "optional": False
}

# ✅ 补充信息设为可选
"距离": {
    "resourceId": "...",
    "optional": True  # 有些职位可能不显示距离
}
```

## 🐛 已知限制

1. **textPattern 性能**
   - 多个元素时需要逐个正则匹配
   - 影响较小（通常只有2-3个元素）

2. **底部标识依赖**
   - 必须存在唯一的底部标识元素
   - 用户需手动验证

3. **滚动精度**
   - 固定步长滚动（0.7 → 0.3）
   - 可能跳过某些元素（概率极低）
