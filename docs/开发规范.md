# 开发规范

## Rule: 文件读写操作必须通过 common/file_manager.py

**所有文件的读写操作必须调用 `common/file_manager.py` 中提供的方法**，禁止直接使用 `open()`、`Path.read_text()`、`Path.write_text()`、`Path.write_bytes()` 等底层 I/O 操作。

- JSON 读写：使用 `read_json()` / `write_json()`（raw/analyzed 目录）或 `read_json_path()` / `write_json_path()`（任意路径）
- 文本读写：使用 `read_text()` / `write_text()`
- 二进制读写：使用 `read_bytes()` / `write_bytes()`
- 目录列举：使用 `list_files()` / `list_json_files()`
- 所有写入自动创建父目录，读取时文件不存在返回 `None` 而非抛出异常

**原因**：统一 I/O 入口，确保目录自动创建、错误处理、日志记录行为一致，避免分散的底层操作导致的路径不一致和异常处理遗漏。

## Rule: 日志输出必须使用 common.logger.log()

**所有日志输出必须调用 `common.logger.log()` 方法**，禁止直接使用 `print()`、`logging.info()` 等。

- `log(message, level="INFO", task_id=None)` — 同时打印到终端并推送 SSE
- 支持 `task_id` 参数时，日志会自动关联到对应的 SSE 队列

**原因**：统一日志格式，确保终端输出和前端 SSE 推送一致，避免日志分散在多处。
