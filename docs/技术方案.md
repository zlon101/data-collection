# 技术方案

当前实现架构（以代码为准）。旧版「仪表盘改造方案」已落地或废弃，本文不再保留改造清单。

## 1. 概述

uv Workspace Monorepo：FastAPI + Vue3 仪表盘 + Playwright/App 采集 + LangChain（百炼 Qwen）。数据以 JSON 文件落在 `local_data/`。

浏览器采集默认 **CDP 连接已开调试端口的 Chrome**（`BrowserManager(mode="connect")`）。自然语言配置由根目录包 `scrape_agent`（LangGraph）生成，**不替代**前端手动填表。

## 2. 技术栈

| 模块 | 技术 |
|------|------|
| 包管理 | uv workspace |
| 后端 | FastAPI |
| 前端 | Vue3 + Vite + **Ant Design Vue** + ECharts + axios |
| LLM | `ai_agent.create_llm()`：`ChatOpenAI` + `ALIBABA_API_KEY` / `ALIBABA_API_URL`，默认模型 `qwen-plus` |
| 网页采集 | Playwright；CDP `connect` / `launch` |
| 配置 Agent | LangGraph（`scrape_agent`） |
| 移动端 | Airtest（独立 venv）/ uiautomator2 |
| 存储 | `local_data/` JSON，`common/file_manager` |

LLM 必须走 `create_llm()`，不要用 Crawl4AI/LiteLLM 调百炼（与项目模型名、兼容网关不兼容）。

## 3. 逻辑架构

```
自然语言 CLI (scrape_agent)          前端 Tab：爬虫 | 查询
        │                                    │
        │ 试抓确认后调用 launcher              │ POST /api/collector
        ▼                                    ▼
   BrowserManager (CDP)  ←── 同一 Chrome ─── 采集 launcher
        │
        ├─ UniversalScraper     列表 / 分页（next 按钮）
        └─ MergedScraper        列表 + 详情（url goto 或 click 列表项）
        │
        ▼
   local_data/raw | job | analyzed
        ▲
        └── FastAPI 读写；Query 页展示 job 表格
```

| `collection_platform/app_uiautomator2/` | Boss / 智联 |

Workspace members：`backend`、`ai_agent`、`browser_playwright`、`app_uiautomator2`、`wx`、`visualization`、`common`、`scrape_agent`。

## 5. 核心流程

### 5.1 前端手动采集

1. `./scripts/run_chrome.sh`，打开目标页  
2. `uv run uvicorn backend.main:app --reload --port 8000`  
3. `cd frontend && npm run dev`  
4. 「爬虫」填 URL / 选择器 / 字段（可选手动开详情）→ 启动 → `/api/collector` → `run_browser_scraper` / App launcher  
5. 「查询」读 `local_data/job`，筛选活跃度 / 薪资 / 距离；Job 文件管理、已读  

日志在爬虫任务弹窗，**没有**独立日志页。

### 5.2 scrape_agent（自然语言）

```
parse_intent → propose_config → sample_scrape → interrupt(y/n)
                    ↑                    │
                    └── 否 ───────────────┘
                                         是 → full_scrape → END
```

- `parse_intent`：`create_llm()` 抽出 url、模块选择器、列表字段、是否详情、详情字段、`max_pages`  
- `propose_config`：CDP 取 HTML，LLM 生成 `container_selector` / `fields` / 可选 `next_button_selector`；详情且无真实 href 时 **点击第一条** 再生成 `detail_*`，`detail_entry=click`  
- `sample_scrape`：仅列表则当前页 2～3 条；含详情则 **1 条列表+详情**  
- `full_scrape`：`run_browser_scraper`（分页 `max_pages`、详情 click/url）  

Chrome 必须已开远程调试并打开目标页。端口：`.env` 的 `CDP_URL`；连接失败会探测 `9222/9422/9223/9224`。

### 5.3 列表分页

`UniversalScraper.scrape_with_pagination`：有 `next_button_selector` 则点下一页。`max_pages=0` 表示不限。Agent 指令「前 N 页」→ `max_pages=N`。

### 5.4 列表 + 详情

`MergedScraper`：列表项 → 详情 → 回列表 → 下一项。结果 `{ list_data, detail_data, metadata }`。

| `detail_entry` | 行为 |
|----------------|------|
| `url` | 从列表字段取 `href` 再 `goto`（须为 http(s) 或站点相对路径） |
| `click` | 点击列表容器（适配 `javascript:void(0)`），再 `go_back` |

对齐方式：**顺序处理 + 下标**（`list_page` + `item_index`）。**没有**列表标题与详情标题的交叉校验；SPA 刷新/回错页时存在错配风险（暂不改）。

## 6. API（后端已实现）

数据：`GET /api/files`、`GET /api/data/{filename}`、`POST /api/analyze`、`GET /api/analyze/status/{filename}`、`GET /api/summary`  

Job：`GET /api/jobs`、`POST|DELETE /api/job/read`、`GET|DELETE /api/job/files/...`、`POST /api/job/merge`  

采集：`POST /api/collector`、`POST /api/collector/{task_id}/cancel`、`GET /api/collector/tasks|status|logs`  

配置：`POST|GET|DELETE /api/collector/config...`  

`scrape_agent` **不经**这些接口，CLI 直连采集器。

## 7. 浏览器与 LLM 环境

`.env`：`CDP_URL`、`BROWSER_MODE=connect`、`ALIBABA_API_KEY`、`ALIBABA_API_URL`。`AGENT_MODEL` 若在百炼不存在（例如错误的 coder 名），`create_llm()` 仍默认 `qwen-plus`。

启动调试 Chrome：仓库根目录 `./scripts/run_chrome.sh`（端口来自 `CDP_URL`）。
