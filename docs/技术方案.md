# 技术方案

## 1. 概述

本文档描述基于现有数据采集分析平台的升级改造方案，目标是将当前单页仪表盘重构为 **左右布局的多页应用**，新增 **爬虫配置** 和 **日志查看** 功能，并扩展 **数据查询** 模块以支持招聘数据的表格展示与筛选。

## 2. 需求映射

| 需求 | 实现方案 |
|------|----------|
| 左右布局（左侧菜单 + 右侧内容） | `App.vue` 重构为 Layout 容器，使用 `ant-design-vue` 的 `a-layout` + `a-menu` |
| 爬虫：数据抓取 + 配置参数 | 新增 `/api/collector` 路由 + SSE 实时推送日志，前端表单配置采集参数 |
| 查询：job 数据表格 + 筛选 | 新增 `/api/jobs` 路由读取 `local_data/job/`，前端 `a-table` 展示 + 筛选栏 |
| 日志：SSE 实时推送 | 通用 `log()` 函数，采集器调用后同时打印终端 + 推送 SSE 到前端，集成在爬虫页面展示 |
| 技术栈 | vite + vue3 + ant-design-vue + axios（新增 `ant-design-vue`） |
| 删除原有仪表盘 | 移除情感分布/实体词云/文章列表等旧组件 |

#### 4.1.2 通用日志函数 `common/logger.py`

不使用日志缓冲区、不写磁盘文件。一个通用 `log()` 函数，同时完成：
1. 打印到终端（stdout）
2. 通过 `asyncio.Queue` 推送给所有已连接的 SSE 客户端

```python
# common/logger.py
import asyncio
import sys
from datetime import datetime

# task_id → list[asyncio.Queue]，一个任务可有多个 SSE 连接
_subscribers: dict[str, list[asyncio.Queue]] = {}


def _make_entry(message: str, level: str) -> str:
    ts = datetime.now().strftime("%H:%M:%S")
    return f"[{ts}] [{level}] {message}"


def register_queue(task_id: str) -> asyncio.Queue:
    """注册一个队列到指定任务，返回该队列供 SSE 端消费。"""
    q: asyncio.Queue[str] = asyncio.Queue()
    _subscribers.setdefault(task_id, []).append(q)
    return q


def unregister_queue(task_id: str, q: asyncio.Queue) -> None:
    """SSE 断开时清理。"""
    queues = _subscribers.get(task_id, [])
    if q in queues:
        queues.remove(q)
    if not queues:
        _subscribers.pop(task_id, None)


def log(message: str, level: str = "INFO", task_id: str | None = None) -> None:
    """通用日志：打印到终端 + 推送 SSE。

    Args:
        message: 日志内容
        level: 日志级别 (INFO/WARNING/ERROR)
        task_id: 关联的任务 ID，为 None 时不推送 SSE
    """
    entry = _make_entry(message, level)
    # 1. 打印到终端
    print(entry, flush=True)
    # 2. 推送给该 task_id 的所有 SSE 队列
    if task_id and task_id in _subscribers:
        payload = f"event: log\ndata: {{"timestamp": "{entry[:8]}", "level": "{level}", "message": "{message}"}}\n\n"
        for q in list(_subscribers[task_id]):
            q.put_nowait(payload)
```

**使用方式**：采集器代码中调用 `log("开始抓取...", task_id=task_id)` 即可同时输出到终端和推送 SSE。

#### 4.1.3 爬虫触发 `POST /api/collector`

```
POST /api/collector
Body:
  {
    "type": "app_uiautomator2" | "browser_playwright",
    "params": { ... }
  }
Response:
  { "status": "accepted", "task_id": "..." }
```

**实现要点**：
- 复用现有采集器模块（`collection_platform/` 下的各子模块）
- 通过 `BackgroundTasks` 异步执行采集任务
- 任务状态跟踪与 `/api/analyze/status/` 类似，使用内存字典
- 采集结果写入 `local_data/raw/` 或 `local_data/job/`

#### 4.1.4 采集日志 SSE 推送 `GET /api/collector/sse/{task_id}`

```
GET /api/collector/sse/{task_id}
Response: StreamingResponse (text/event-stream)

event: log
data: {"timestamp": "...", "level": "INFO", "message": "..."}

event: complete
data: {"status": "done", "task_id": "..."}

event: error
data: {"error": "..."}
```

**实现要点**：
- SSE 端连接时调用 `register_queue(task_id)` 获取一个专属 `asyncio.Queue`
- 使用 `async for` 循环从 Queue 读取事件并 yield
- 采集任务中通过 `log(message, task_id=task_id)` 推送日志
- 任务结束时向 Queue 推送 complete/error 事件后关闭

### 5.7 SSE 客户端工具 (`api/sse.js`)

```javascript
export function createEventSource(taskId, handlers) {
  const es = new EventSource(`/api/collector/sse/${taskId}`)

  es.addEventListener('log', (e) => {
    handlers.onLog?.(JSON.parse(e.data))
  })
  es.addEventListener('complete', (e) => {
    handlers.onComplete?.(JSON.parse(e.data))
    es.close()
  })
  es.addEventListener('error', (e) => {
    handlers.onError?.(JSON.parse(e.data))
    es.close()
  })

  return es
}
```

## 6. 数据流

### 6.1 爬虫数据流

```
用户配置参数 → POST /api/collector → 创建 task_id + Queue
  → BackgroundTasks 启动采集器（采集器调用 log(message, task_id) 推送）
  → 采集结果写入 local_data/raw/ 或 local_data/job/
  → 前端 EventSource 连接 /api/collector/sse/{task_id} 实时接收日志
  → 收到 complete 事件 → 显示"采集完成"
```

### 6.2 查询数据流

```
用户点击"查询" → GET /api/jobs?activity=...&min_salary=...&max_distance=...
  → 后端读取 local_data/job/*.json → 合并/去重/过滤
  → 返回 JSON → 前端 a-table 渲染
```

## 8. 已确认决策

1. **爬虫配置参数**：
   - **app_uiautomator2**：暴露 `config.py` 中的全部 7 个参数（MAX_DISTANCE、MoneyMin、JobKeys、BlackCompany、max_items、is_search、is_new_job_list），默认值取代码中的值
   - **browser_playwright**：暴露 `create_scraper_config` 的配置项（url、fields、container_selector、next_button_selector、max_pages、delay）+ `output_filename`

2. **日志**：不使用日志缓冲区、不写磁盘文件。使用一个通用 `log(message, level, task_id)` 函数，同时打印到终端并通过 `asyncio.Queue` 推送 SSE。日志查看集成在爬虫页面中，通过 EventSource 实时接收

3. **job 数据源**：由程序写入 `local_data/job/` 目录（爬虫自动写入）

4. **原有仪表盘**：删除，不再保留情感分布/实体词云/文章列表等功能
